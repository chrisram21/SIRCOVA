# Notas · usuarios

Cuentas, personal, CUI y contraseñas temporales. Specs en `specs/usuarios/`. Una nota por línea, corta y con la fecha (AAAA-MM-DD). Dónde va cada nota: «Notas de contexto» del `CLAUDE.md` de la raíz.

- 2026-10-22: seguridad de cuentas (SPEC 10): toda contraseña temporal la genera `generarContrasenaTemporal` (`modulos/auth/contrasenaTemporal.service.js`, largo en la constante `LARGO`, hoy 12) y el backend la devuelve una sola vez (`POST /usuarios` y `POST /usuarios/{id}/restablecer-contrasena`); `POST /usuarios` responde 400 si el cuerpo trae `contrasenaTemporal`. Las pruebas la comprueban con `bcrypt.compare` contra el hash, sin iniciar sesión. `RESTABLECER_CONTRASENA` se registra aunque `diferencias` dé `null` (excepción escrita en el spec).
- 2026-10-22: CUI del empleado (SPEC 11): se guarda solo `empleado.cui_hmac`, el HMAC-SHA256 del CUI calculado con `huellaCui` (`modulos/usuarios/cui.service.js`) y la clave `CUI_HMAC_CLAVE` de `backend/.env` (al menos 32 caracteres; sin ella la API no arranca). La clave es **la misma para todo el equipo** (la reparte Luis) y no se cambia: con otra, las huellas guardadas ya no coinciden. La API nunca devuelve el CUI ni la huella, solo `cuiRegistrado`; `cui`, `cuiHmac` y `cui_hmac` están en `CLAVES_SENSIBLES`. Las pruebas usan CUI ficticios generados al azar con su verificador (`cuiFicticio` en `usuarios.test.js`), nunca CUI reales.
